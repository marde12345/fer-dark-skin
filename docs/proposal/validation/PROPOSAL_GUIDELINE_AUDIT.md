## 2. Focused Findings on the "Pay Particular Attention To" Items

- **Official Research Question**: Confirmed absent. This is not a new finding — the repository's own R9 documentation (`docs/R9_FINAL_STATISTICAL_VALIDATION.md`, "Research Question Readiness" table) already states this explicitly and calls it a thesis-author decision. This audit confirms that status is unchanged and is the single largest structural blocker in the table above, since Gap, Objective, Requirements, Artifact-justification, Evaluation-architecture, and Contribution-chain all formally depend on it per the guideline's traceability chain.
- **Is the practical problem supported by evidence?**: Partially. The *symptom* (Neutral→Angry misclassification, 23.7% of Neutral ground truth in the historical N=227 population, reconfirmed on the N=135 common subset) is well-evidenced and numerically consistent across every experiment that touches it. What is missing is the guideline-required *practical-problem structure* around that symptom: whose goal is unmet, what the consequence is, and why it is a research-worthy gap rather than only an observed data pattern.
- **Is the research gap actually established?**: No. A gap cannot be established without a literature review, which does not exist. The repository has so far correctly avoided asserting an unverified gap (no "no one has done this" language appears anywhere in R1–R9), which is good discipline to preserve, not a state to relax when the proposal is drafted.
- **Does the current ArcFace experiment logically follow from the problem/gap?**: No — and the repository's own `docs/RESEARCH_FRAMING.md` already surfaces this tension: the *author's stated intent* names ArcFace as the method before a problem/gap analysis was done, which is the reverse of the guideline's required Problem→Evidence→Knowledge→Gap→RQ→Objective→Requirements→Artifact order. The experiment itself is methodologically sound as *exploratory empirical work*, but is not yet positioned as the *output of* a design-research argument chain — it is currently the *input* that a chain would need to be built around, or independently re-justified through Problem→Gap→RQ→Requirements once those exist.
- **Is ArcFace correctly described as a frozen face representation/feature extractor?**: Yes, consistently, across all reviewed documentation (`docs/METHODOLOGY_RECONCILIATION.md`, `docs/ARCFACE_EXPERIMENT_DESIGN.md`, `tools/extract_arcface_embeddings.py`, `docs/RESEARCH_FINDINGS.md`). No instance of ArcFace being described as an expression classifier or as producing an "Angry" prediction was found in any file reviewed for this audit.
- **Is Logistic Regression correctly described as the expression classifier?**: Yes, consistently (`tools/train_arcface_classifier.py`, `docs/RESEARCH_FINDINGS.md` §1–2).
- **Is HSEmotion correctly described as the baseline expression classifier?**: Yes, consistently.
- **N=227 historical vs. N=135 controlled comparison distinction**: Correctly and consistently maintained throughout every document reviewed (`docs/RESEARCH_FINDINGS.md`, `docs/R9_FINAL_STATISTICAL_VALIDATION.md`, `tools/build_dashboard_data.py`, the dashboard). No instance was found in the reviewed research documentation where the two populations were merged or conflated. This distinction has been a durable strength of this repository since at least R9 and should be preserved unchanged into any future proposal writing.
- **Current 5-class evaluation scope**: Correctly and consistently documented as a ground-truth-level limitation (Angry=1, Disgust=2 across all population stages: 227 full → 144 valid → 138 embedded-valid — `docs/R7_5_CLASS_DECISION.md`), not an ArcFace pipeline artifact, and not resolved by threshold-lowering or reweighting.
- **The unsupported historical "100% dark-skinned" claim**: Already identified and corrected *internally* (R2, `docs/THESIS_RQ_ALIGNMENT.md`; restated in `docs/RESEARCH_FINDINGS.md` §10 as an explicitly rejected claim, with the actual 58.8%/41.2% Dark/Medium-Dark split of the characterized subset cited). This is a resolved internal contradiction, not an open one — but it is flagged here as a **risk to re-introduce** if proposal text is drafted from memory/older narrative material (e.g., `Tesis_Knowledge_Transfer_(1).md`, referenced in `docs/R9_FINAL_STATISTICAL_VALIDATION.md` as still requiring direct author reconciliation) rather than from the corrected documents.
- **Skin tone vs. ethnicity**: Consistently and correctly separated throughout all reviewed documents. No file reviewed treats skin-tone bucket as an ethnicity label or as a Papuan-specific measurement.
- **Observed association vs. causal/fairness claims**: Consistently conservative. The Fisher's exact test result (OR=5.88, p=0.0027, Dark vs. Medium-Dark HSEmotion accuracy) is uniformly described as an in-sample association, never as bias, causation, or an ethnicity-specific effect, across every document reviewed.
- **Are current experiments sufficient to support the proposed research contribution?**: Not yet assessable — because no Contribution has been formally proposed for a specific RQ. The *evidence* is sufficient to support several conservatively-scoped contribution claims (see `docs/RESEARCH_FINDINGS.md` §9), but "sufficient for *the* contribution" cannot be evaluated until a specific RQ/Objective/Artifact chain exists to check the evidence against.
- **Is the artifact actually defined?**: No, not in the guideline's formal sense (type, purpose, mechanism, components, Table 11.2). A working instantiation exists and has been evaluated, but its guideline-compliant specification has not been written — this is exactly Phase 6's job.
- **Is the methodology currently justified?**: No formal justification/comparison exists (see Methodology row). The actual sequence of work is well-documented and traceable, but has not been named or defended as a chosen design-research methodology.
- **Is the evaluation architecture sufficient for the intended claims?**: The *metrics* are sufficient and rigorous for the claims already made in `docs/RESEARCH_FINDINGS.md` (which are conservatively scoped to match). Whether they will be sufficient for a *future*, not-yet-written RQ's claims cannot be determined yet — that depends on what RQ is chosen.
- **Is novelty supported or still unknown?**: Still unknown, and cannot become known without a literature review. This is accurately reflected as `MISSING / BLOCKED`, not `WEAK`, in the table above, since "unknown until reviewed" is a different (and more honest) state than "reviewed and found weak."

## Key Findings

- **The single largest structural blocker is the absent official Research Question** — the repository's own prior documentation already states this, and this audit confirms every downstream element (Gap, Objective, Requirements, Artifact justification, Evaluation Architecture, Contribution) is currently either `MISSING`, `WEAK`, or only `PARTIALLY READY` because it has no RQ to trace back to.
- **Literature review is completely absent** (`Existing Knowledge`, `Existing Solution`, `State of Art` all `MISSING`), which blocks `Gap` and makes `Novelty` formally `BLOCKED` rather than assessable.
- **The empirical/experimental work itself is the repository's strongest area** — `Evaluation` (technical rigor), `Feasibility` (substance), and `Contribution` (raw material) are all `PARTIALLY READY` or better, because R5–R9 already produced cross-validated, consistency-audited, conservatively-scoped results. The gap is almost entirely in the *upstream design-research framing* (Problem→Gap→RQ→Objective→Requirements→Artifact-specification→Methodology-justification), not in scientific rigor.
- **No experiment result was found to be READY-by-default** — per the task's explicit instruction, nothing was marked `READY` merely because a related experiment exists; every `READY`/`PARTIALLY READY` rating above is tied to a specific guideline requirement being met, not to the existence of R1–R9 work in general.
- **One structural tension is flagged, not resolved**: the author's original research framing names "ArcFace" as the method inside the problem statement, which runs counter to the guideline's solution-neutrality principle. This does not need to be fixed in this phase, but Phase 2 (Problem Architecture) should build the practical/knowledge/design problem statement independently of the ArcFace framing, and only reconnect to ArcFace later if the requirements/artifact-selection logic actually supports it.
- **Ethics is the one area with a genuine, not-yet-addressed content gap** (data provenance/consent for the "Pesta Babi" film source, face-crop data handling policy, misuse-risk statement) rather than a framing/ordering issue like most other rows.
